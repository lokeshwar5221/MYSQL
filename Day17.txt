stored procedures
=====================
A stored procedure is named,precompiled collection of one or more sql statements that are stored 
inside the database and can be executed(called) whenever required. inside of semding a long block of sql from an application every time,the application simply calls the procedure by name

stored procedure behave likes function or suboutines in programming language, they can accept
parameters,preform logic(loops,condition,variable declarations) and return result.

why use stored procedures?
---------------------------
performance : precompile and cached by the database engine, so repeated execution is faster than sending raw sql each time

reusability : Write the logic once , call it from many applications or scripts.

security : Users can be granted execute permission on a procedure without granting direct access to the underline tables.
  
reduced network traffic : a single call statement replaces many lines of SQL sent over the network .

Maintainability : Business logic is centralized in the database , so changes are made i none place .

consistency : Ensures the same validation/business rules are applied everytiem , regardless of which application 
calls it.

Advantages
------------
faster execution after compilation 
reduce duplicate sql
support transaction,loop,condition,variable,curious, and exception handlers
easy maintance

disadvantages
---------------
debugging can be difficult
vendor specific syntax
complex procedure may become hard to maintain

syntax
----------
DELIMITER //

CFEATE PROCEDURE procedure_name(
[IN | OUT | INOUT]parameter_name data-type,..........
)
BEGIN
---------SQL statements/logic
---------Decleration,condition,loops...etc
END //

DECLIMITER ;


call procedure_name
